# 01. Frontend

## Folder purpose

Flutter screens, navigation, state, theme, and reusable presentation. The current app remains in the repository's existing `lib/` layout; do not move files just to match this planning folder.

## Current status

Starter screen only; most feature source is absent.

## Plan

1. Confirm the first user workflow and its approved states.
2. Establish the app composition, theme, navigation, typed UI state, and shared feedback patterns.
3. Add feature folders only as approved screens and workflows are implemented.
4. Keep Firebase and other SDK calls out of widgets. Present loading, empty, failure, and offline states where relevant.

## Ready when

The selected workflow works locally and the UI presents only data the signed-in role may access.
